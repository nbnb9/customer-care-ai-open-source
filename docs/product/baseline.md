# P0 无 AI 人工处理基线

> 本文记录的是**合成场景**下的基线，不是真实生产数据。

## 场景与来源

- 数据：`data/fixtures/world.json`（两租户合成世界，source: synthetic）
- 无 AI：P0 全程由确定性规则处理，无模型参与

## 基线口径

| 指标 | 合成场景值 | 说明 |
|---|---|---|
| 人工分诊步骤数 | 1（客户提交 → 坐席队列） | P0 无自动分诊，人工领取 |
| 一次完成 / 转交次数 | 未定义 | 合成 fixture 不含真实转交路径 |
| 重复提交问题 | 历史基线存在 | 2026-08-16 的 P0 基线没有幂等保护；见下方修补状态 |
| 处理耗时 | 未度量 | P0 无 SLA/计时逻辑 |

## 2026-08-18 修补后状态

- `POST /v1/tickets` 现在强制提供 `Idempotency-Key`。
- 同一租户、主体、操作和 key 的相同请求重放返回首次响应快照，不重复创建工单、事件或审计记录。
- 同一幂等作用域复用 key 但改变请求体会返回 HTTP 409；并发重放由数据库唯一约束收敛为一个业务对象。
- 以上是合成测试环境中的正确性结果，不是生产重复提交率，也不改变本页“历史 P0 基线”的时间口径。

## 用途

P1 接入模型后，用同样的合成场景对比：分诊耗时、一次完成率、重复提交率等。只有先有这条无 AI 基线，才能判断 AI 是否真的改善了指标。

## 边界

不虚构 FCR、CSAT 等生产级数字。所有数字必须来自可复现的合成 fixture 与测试。
