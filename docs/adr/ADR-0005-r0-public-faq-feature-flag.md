# ADR-0005：客户 R0 自助采用服务端公开证据灰度开关

- 状态：已采纳
- 日期：2026-08-24

## 背景

步骤 29 已提供 ACL 优先的检索和受证据约束的回答，步骤 32 已提供客户会话、持久事件和人工升级。把两者直接连接会扩大客户面：若只依赖浏览器按钮、环境变量或模型自行判断，订单、退款、账户、隐私等非 R0 输入可能绕过控制，且无法对小范围客户即时停止。

## 候选方案

1. 只在浏览器隐藏/显示 FAQ 按钮，并继续直接调用知识回答接口。
2. 仅用部署环境变量按全局启用 R0。
3. 使用部署主开关加租户数据库灰度开关；会话服务端先判定风险，再仅以 `public` 受众进行受证据回答，并把引用、反馈和升级写入持久事件。

## 决策

采用方案 3。

- `R0_SELF_SERVICE_MASTER_ENABLED` 默认 `false`，作为发布面的全局保险；它只能随受控部署配置改变。
- `r0_self_service_feature_flags` 按租户保存 `enabled`、显式客户名单或明确的全租户选项。只有同租户主管可写，修改有审计记录。每个客户消息从数据库读取该值，因此 `enabled: false` 是即时租户级停止开关。
- 任何 RAG/模型调用前，用确定性规则拦截订单/物流、账户变更、安全、支付/退款/退货、投诉、隐私、登录和人工请求。它们创建 `handoff.created`，而非生成 FAQ。
- R0 调用复用知识回答服务，但限制为 `audiences=("public",)`；产品和语言由部署配置拥有，地区仍由已验证的客户身份绑定。只有当前有效、可信、词面命中的证据及服务器验证的引用可以进入 `answer.completed`。
- 模型返回后再次检查有效开关。R0 不发送文本 delta，最终答复在持有租户开关行锁的事务中才持久化；若关闭、无证据、版本冲突、模型不确定或引用无效，写入系统升级通知与人工升级，而不把草稿或无引用文本发送给客户。
- 反馈仅允许绑定已完成的 `r0_self_service` 助手消息，并通过会话、回答消息、客户唯一约束保存最新显式评价。它是质量信号，不是自动化决策依据。

为防止旧前端或脚本绕过会话路径，客户调用 `POST /v1/knowledge/answer` 同样经过主开关、风险拦截、部署拥有的产品/语言范围和 `public` 受众限制；客户支持页移除直接知识问答入口。

## 后果

正面结果：

- 可把 R0 暴露面限制到明确的合成 Demo 租户/客户，并且不依赖浏览器或模型守规矩。
- 引用、原文重新授权、人工升级和反馈沿用已有的服务端审计/恢复语义。
- 无证据和高风险输入不退化为貌似权威的 FAQ 回答。

成本与限制：

- 当前关键词策略会产生保守的误升级；它不是完整意图分类器，也不是可执行售后编排。
- 数据库逐消息读取适合当前单体基线；高吞吐场景需要配置分发、缓存失效协议和审计告警，且不能牺牲关闭的即时性。
- `BackgroundTasks` 仍不是 durable queue；进程崩溃恢复、幂等外部副作用、真实身份、数据保留/删除、指标和人工运营流程未完成。
- 测试使用 Fake 网关和合成知识。通过本 ADR 不代表真实供应商、生产资料或企业级发布批准。

## 验证

- 默认关闭、非主管拒绝、跨租户名单拒绝，以及主管审计记录均有 API 测试。
- 灰度客户能获得仅 `public` 的带引用 R0 回答；同租户非灰度客户获得非政策确认。
- 订单、退款、登录、隐私和人工请求不会调用知识回答，直接创建人工升级。
- 无公开证据、旧直接接口、高风险查询和模型后关闭都不会泄露 R0 草稿或内部/客户受众资料。
- 客户反馈可幂等重放、可更新且产生持久 `feedback.recorded` 事件；Web E2E 验证引用原文与反馈交互。
