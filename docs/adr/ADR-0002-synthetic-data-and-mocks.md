# ADR-0002：开发期只使用合成数据和 Mock 外部系统

- 状态：已采纳
- 日期：2026-08-12

## 背景

真实客户、订单和聊天数据可能包含个人信息、商业秘密和权限限制。简单删除姓名不等于数据已经安全，也无法保证不可重新识别。

## 候选方案

1. 直接使用生产数据。
2. 使用经过简单脱敏的真实导出。
3. 使用完全合成的数据和 Mock CRM/OMS。

## 决策

Local 和 CI 只使用从零生成的合成数据。CRM、OMS 和物流系统使用确定性的 Mock 或契约 Stub，不连接真实账户。

Fixture 使用明显的合成标记，例如 `SYNTH-CUSTOMER-001` 和 `example.com`。

## 后果

正面结果：

- 降低隐私和合规风险。
- 测试可以重复运行和重置。
- 更容易构造越权、失败和边界案例。

成本与限制：

- 合成数据不能覆盖所有真实业务分布。
- Mock 可能与真实系统行为产生偏差。
- 接入沙箱前必须补充契约测试。

## 验证

- 仓库中不包含生产导出文件。
- Fixture 带有明确的合成标记。
- Local 和 CI 配置中没有生产 URL 或真实凭据。
- `data/private/`、`data/raw/` 和 `.env` 被 Git 忽略。
- Mock 可以稳定模拟成功、超时、拒绝和重复请求。
