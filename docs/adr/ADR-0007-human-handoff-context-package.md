# ADR-0007：人工升级采用服务端路由与最小上下文包

- 状态：已采纳
- 日期：2026-08-25

## 背景

步骤 32–34 已能创建 `requested` 人工升级，但它只有原因码和创建时间：主管不能按 SLA 查看待办，坐席也无法在不阅读完整会话的前提下接手。若把完整聊天记录、系统 Prompt、模型隐式推理或未脱敏 Trace 直接给队列，会把客户数据和内部控制面扩散给不需要它们的角色。

人工请求、R2/R3 风险拦截、身份不足、R0 无证据、R0 系统故障和连续回答失败都需要一个确定性的人工接管入口；浏览器或模型均不应决定优先级、目标队列或 SLA。

## 候选方案

1. 继续只保留 `requested` 状态，由坐席打开完整会话记录自行判断。
2. 由浏览器提交优先级、队列、SLA 和上下文文本。
3. 将完整会话/Trace 复制到通用坐席队列。
4. 服务端根据原因码路由，保存受限、脱敏的快照，并以独立 staff API 交付给获授权角色。

## 决策

采用方案 4。

- `ConversationHandoff` 扩展为服务器决定的 `priority`、`target_queue`、`sla_due_at`、领取人、领取/完成时间与 `context_snapshot`。原因码到路由的映射固定在服务端；客户请求体只能表达 `customer_requested`。
- 快照固定为 `handoff-context-v1`，仅有验证等级、会话摘要、系统观察到的事实、与会话因果关联的工具摘要、客户已见引用、脱敏后的未解决问题和风险原因。当前 R1 工具还没有会话关联 ID，因此工具摘要诚实地为空，不能从不相关的审计记录猜测结果。
- 上下文不复制系统 Prompt、模型隐式推理、其他客户信息或完整 Trace。摘要中的客户原文先经过确定性直接标识脱敏并限制长度；R0 引用只从已经发送给客户的 `answer.completed` 事件提取，且仅保留标题、版本、片段和客户已见的相对来源定位。
- `GET /v1/handoffs` 与 `GET /v1/handoffs/{id}` 只对当前租户 agent/supervisor 开放。普通坐席只看待领取或自己已领取的升级；主管可看本租户队列。跨租户 ID 统一为 404。
- 坐席领取和结束自助会话要求 `Idempotency-Key`，均写 `handoff.updated`、`workflow.updated` 与审计事件。`restore_safe_flow` 只把会话移到 `awaiting_customer`；它不重新打开模型自动回复入口。
- 由于当前 Demo 没有安全专员角色，`safety-review` 队列只允许 supervisor 查看、领取和结束，普通 agent 不能看到或处理它。真实系统必须以 IdP scope/队列成员资格替代这个暂时的角色映射。
- 已知客户会话在验证等级不足时不会持久化该次输入，而是写系统通知和 `identity_verification_required` 升级。没有可确认客户归属的预认证请求仍在身份边界拒绝，不伪造客户或会话归属。
- 普通生成失败第一次仍提供重试/人工入口；同一会话第二次失败自动生成 `system_generation_repeated_failure` 紧急技术队列升级。R0 生成故障和无证据沿用即时升级。

## 后果

正面结果：

- 客户升级、自动升级、主管可见队列、坐席接手和结束自助会话形成可审计闭环。
- 坐席看到的是小而可验证的 DTO，而非完整客户时间线或内部推理。
- 客户 SSE 不收到路由队列、SLA、指派人或上下文快照；浏览器不能篡改这些字段。

限制与后续门禁：

- 直接标识脱敏是有限的规则集，不等于生产 DLP、敏感实体识别、保留/删除/加密策略或法律合规批准。
- SLA 目前只是持久化截止时间，没有队列消费者、超时告警、排班、自动重分配、Outbox 或升级策略。
- `BackgroundTasks`、数据库轮询 SSE、Demo Header 和本地合成数据仍不能用于生产人工运营。
- 当前没有真实 OMS/CRM 会话关联，故上下文包不能诚实报告 R1 工具执行结果；后续工具编排必须携带因果关联 ID 后再填充该字段。

## 验证

- API 测试覆盖客户最小响应、当前租户队列、跨租户隐藏、上下文直接标识脱敏、客户可见引用、领取/关闭/安全恢复、事件/审计/幂等、身份不足和连续失败自动升级。
- API 测试验证普通坐席不能查看或领取 `safety-review`，主管可处理该队列。
- Playwright 覆盖客户请求人工、主管查看上下文包、坐席领取并关闭的浏览器闭环。
