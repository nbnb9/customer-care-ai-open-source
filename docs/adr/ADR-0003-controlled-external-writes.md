# ADR-0003：模型不能直接执行外部写操作

- 状态：已采纳
- 日期：2026-08-12

## 背景

模型输出具有不确定性。退款、取消订单、地址修改等写操作会产生真实副作用，不能由自然语言结果直接触发。

P0 不使用模型，但现在需要固定后续阶段的安全边界。

## 候选方案

1. 让模型直接持有 CRM/OMS 凭据并调用写接口。
2. 模型只生成结构化建议，由 Tool Adapter 和 Workflow 控制写操作。
3. 永远不允许系统接入外部写操作。

## 决策

P0 完全不接入模型。

后续阶段中，模型只能生成结构化建议或草稿。所有外部写操作必须经过服务端权限检查、参数校验、策略、用户确认或人工审批、幂等控制和审计，再由 Tool Adapter 执行。

模型和业务模块不得持有 CRM/OMS 凭据。

## 后果

正面结果：

- 防止模型绕过权限和业务规则。
- 写操作可以审计、拒绝、重试和补偿。
- 供应商模型可以替换，不绑定业务流程。

成本与限制：

- 需要额外实现 Workflow、Tool Adapter 和策略层。
- 写操作链路更长。
- 必须设计状态机、幂等和失败恢复。

## 验证

- 模型进程无法读取外部系统凭据。
- 直接写外部系统的尝试被拒绝。
- 重复 Idempotency-Key 不产生重复副作用。
- 未确认或未审批的操作不能执行。
- 每次执行记录操作者、请求参数摘要、结果和审计标识。
- 外部系统失败时不得向用户显示虚假成功。
